Yes, the length of your documents could indeed be causing the RecursionError: maximum recursion depth exceeded while calling a Python object. This error typically occurs when the depth of the call stack exceeds Python's maximum recursion limit. In the context of the RecursiveRetriever class in LlamaIndex, this could happen if the documents you're working with have a deeply nested structure that causes the _retrieve_rec method to be called recursively many times.

Even though you've tried adjusting the recursion limit in Python using sys.setrecursionlimit(), this is generally not a recommended solution because it can lead to a crash if it exceeds the stack depth limit of your Python interpreter.

One solution could be to refactor the _retrieve_rec method to use an iterative approach instead of a recursive one. This could involve using a stack or queue data structure to keep track of the nodes that need to be processed, and then processing each node in a loop until there are no more nodes left to process.

Another solution could be to simplify the structure of your documents. For example, you could try flattening the hierarchical relationships in your documents, or breaking your documents up into smaller, less complex pieces.

Finally, you could try reducing the similarity_top_k parameter in your VectorStoreIndex retriever. This parameter controls the number of most similar nodes that the retriever returns, and reducing it could help to limit the depth of the recursion.
